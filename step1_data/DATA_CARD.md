# Step 1 분류기 데이터 v2 (2026-10-04)

한국어 프롬프트 인젝션 탐지 Step 1 분류기(KoELECTRA·mDeBERTa) 학습·평가용 데이터입니다.
영어 공개 데이터를 DeepL로 번역한 문장과 한국어 원본 문장으로 구성됩니다.

- v1 (2026-10-03): 원문 `train` / `valid` / `test` / `kg_test`
- v2 (2026-10-04): 증강 학습 데이터, 17종 난독화 평가셋 추가 (v1 파일은 바뀌지 않음)

> **배포 금지**: xTRam1 데이터(라이선스 미표기)가 포함되어 있어 팀 내부에서만 사용합니다.

## 3. 만든 과정

1. **정리**: 인코딩 깨짐 수리, 영문 원문 300자 초과 제외, 라벨 충돌·중복 제거, 정상 데이터 중 탈옥 표현이 있는 문장 제외, xTRam1 공격의 같은 틀은 최대 75건
2. **정상 추출 (짝 맞추기)**: 공격 출처마다 같은 수의 정상을 같은 길이 분포로 추출
    - xTRam1 공격 ↔ xTRam1 정상
    - gandalf 공격 ↔ hh-rlhf + prompts.chat + KoAlpaca(1/3)
    - password, ignore 등 공격에 자주 나오는 단어가 들어간 정상 문장은 우선 포함
3. **번역**: DeepL API (EN→KO, `preserve_formatting=True`, deepl-python 1.32.0)
    - 공격 의미가 사라진 203건은 용어집(prompt → 프롬프트)과 맥락("사용자가 AI 챗봇에게 보내는 메시지")을 지정해 재번역
4. **번역 후 정리**: 정리 함수 재적용, 번역 후 같은 문장이 된 31건 제거, KoAlpaca 중 인젝션·비밀 정보 요구 질문 제외
5. **분할**: 아래 4절
6. **증강·난독화**: 아래 6·7절 (변형기 `komutator`, 스크리닝 셋과 같은 코드)

스크립트는 ko-mutator 레포 `step1_data/`에 있고, 시드는 모두 `20261002`입니다.

## 4. 분할

- **그룹 분할**: 영어 원문 단어가 60% 이상 겹치는 공격끼리 묶고(Jaccard ≥ 0.6), 같은 그룹은 한 분할에만 넣었습니다. 30건 이상인 큰 그룹 6개는 train에 고정했습니다. → test 공격은 train에서 본 적 없는 표현입니다.
- **층화**: (라벨, 출처) 칸마다 train : valid : test ≈ 8 : 1 : 1

- 학습 데이터와 겹치는 문장 0건

## 5. 사용 시 주의

- **`augmented_train`에는 원문 train이 이미 들어 있습니다.** 학습에는 이 파일 하나만 쓰면 됩니다. (팀 레포 `prepare_augmented_train.py`도 이 형식을 그대로 받음)
- **난독화 평가의 주 결과는 `changed=true` 행만**으로 계산합니다. 원문 채점은 `test.jsonl`, `kg_test.jsonl`로 따로 합니다.
- **증강 학습은 데이터가 약 3배**라 같은 epoch이면 학습 횟수도 약 3배입니다. epoch과 step 중 무엇을 맞췄는지 명시합니다.
- valid·test의 xTRam1 짝은 길이 분포 차이(KS 0.16)가 남아 있으므로 **길이 구간별 성능**도 함께 봅니다.
- `max_length` 128 기준 토큰 초과: 원문은 KoELECTRA 0건, mDeBERTa 5건(0.08%, 문장 끝 몇 어절만 잘림). 증강·난독화 파일은 8절

## 6. 증강 학습 데이터 (`augmented_train`)

- **기법**: `yamin_swap` 강도 0.7, `symbol_insert` 강도 0.3
    - 사전 스크리닝(T9b)에서 기준을 통과한 기법이 없어, 규칙에 따라 경계(ambiguous) 2종을 보충 선정한 것입니다.
- **방식**: 공격·정상 모두, 원문 1개당 기법별 변형 1개. 원문과 같은 변형(`changed=false`, 50건 모두 `yamin_swap`)은 제외
    - 정상도 증강한 이유: 공격만 변형하면 "글자가 깨졌으면 공격"이라는 지름길이 생김
- **복제 행(`_dup1`)도 변형**: 복제 행을 빼면 변형 행의 공격 비율이 54.1%로 기울고 길이 보정이 깨집니다. 시드가 `id` 기반이라 복제 행은 원본 행과 다른 위치가 바뀝니다. (같은 결과가 나온 14쌍은 아래 한계 참고)
- **시드**: `int(sha256("20261003|{id}|{기법}|{강도}").hexdigest()[:16], 16)`. 파일 안 순서는 시드 `20261003`으로 섞음

| 칸 (라벨_출처) | 원문 → 증강 |
| --- | --- |
| 공격_gandalf | 785 → 2,329 |
| 공격_xtram1 | 1,616 → 4,848 |
| 정상_hhrlhf | 468 → 1,398 |
| 정상_koalpaca | 265 → 778 |
| 정상_promptschat | 59 → 177 |
| 정상_xtram1 | 1,616 → 4,847 |

- xTRam1 짝 길이 KS: 전체 0.033 / 원문 0.035 / 변형 0.032 (보정 유지)
- 누수: `valid`, `test`, `kg_test`, 난독화 평가셋 2개와 같은 문장 0건

## 7. 17종 난독화 평가셋 (`obfuscated_test`, `obfuscated_kg_test`)

- `test`, `kg_test`의 모든 문장에 17종 × 강도 0.3/0.7 적용. 변형 행만 담음 (원문 행 없음)
- 시드 규칙은 6절과 같음. 스크리닝 셋(고정 시드 20260926)과는 바뀐 위치가 다를 수 있음
- `changed=false` 행은 지우지 않고 표시만 함 (test 393행, kg_test 143행)

| 기법 | 적용률 test 0.3 / 0.7 | 적용률 kg_test 0.3 / 0.7 |
| --- | --- | --- |
| 나머지 14종 | 99~100% / 100% | 99~100% / 100% |
| `yamin_swap` | 97% / 99% | 91% / 99% |
| `vowel_replace` | 85% / 96% | 86% / 96% |
| `continue_sound` | 70% / 91% | 59% / 87% |

- 적용률이 낮은 것은 바꿀 위치가 0~1개인 짧은 문장 때문입니다. (후보 1개 × 0.3 → 반올림 0)
- 기법별 상세: ko-mutator `step1_data/reports/obfuscated_eval_summary.txt`

## 8. 토큰 점검 (팀 학습 설정과 같은 토크나이저)

KoELECTRA는 fast, mDeBERTa는 slow 토크나이저(`--use-slow-tokenizer`)로 측정. 난독화 평가셋은 `changed=true` 행만.

| 파일 | 128 토큰 초과 KoELECTRA | 128 토큰 초과 mDeBERTa | `[UNK]` 포함 행 KoELECTRA | `[UNK]` 포함 행 mDeBERTa |
| --- | --- | --- | --- | --- |
| `augmented_train` | 1 (0.01%) | 87 (0.61%) | 62.0% | 62.1% |
| `obfuscated_test` | 211 (1.05%) | 334 (1.66%) | 30.3% | 57.1% |
| `obfuscated_kg_test` | 0 | 0 | 29.8% | 56.4% |

- `augmented_train`의 `[UNK]` 포함 행은 공격·정상이 비슷합니다 (KoELECTRA 62.3% / 61.6%, mDeBERTa 62.2% / 61.9%). → `[UNK]`가 라벨 지름길이 될 가능성은 낮습니다.
- **두 모델이 깨진 글자를 다르게 처리합니다.**

| 기법 | KoELECTRA | mDeBERTa |
| --- | --- | --- |
| 초성체, 자모 분해, 받침 분리, 무의미 자모 | 대부분 읽음 | 자모가 `[UNK]` |
| 받침 대치, 도상 대치, 기호 삽입, 야민정음 | 단어 전체가 `[UNK]` | 기호 조각만 `[UNK]` |
| 투명문자 | 입력 단계에서 지워짐 (원문과 같게 보임) | `[UNK]`로 보임 |
| 영타, 로마자, 띄어쓰기, 음절 섞기 | `[UNK]` 없음 | `[UNK]` 없음 |

- 야민정음 특수 문자(㉵, º 등)는 두 토크나이저 모두 NFKC로 원래 글자로 되돌리지 않습니다.
- 기법 × 강도별 표: ko-mutator `step1_data/reports/token_check_by_cell.csv`

## 9. 한계

- **범위**: 영문 원문 300자 이하의 짧은 단일 프롬프트만 다룹니다. 긴 탈옥 프롬프트와 긴 문서 속에 숨긴 인젝션은 포함하지 않습니다.
- **말투**: 공격은 "당신은 ~입니다", "~하십시오" 같은 번역투 명령문이 많고, 반말은 대부분 정상(KoAlpaca)에 있습니다. 문장 끝만 보고도 라벨을 어느 정도 맞힐 수 있습니다. (최대 63~68%, 기준 50%)
- **키워드**: "무시", "비밀번호" 등은 공격에 훨씬 많이 나옵니다. 공격의 실제 내용이라 없애지 않았고, 오탐은 `kg_test`의 정상(hard negative)으로 확인합니다.
- **한국어 원본**: 공격은 전부 번역문입니다. 실제 사람이 쓴 한국어 공격에 대한 성능은 확인되지 않았습니다.
- **출처**: gandalf에는 공격만 있어 gandalf 문체 자체가 공격 신호가 될 수 있습니다.
- **근접 중복**: 번역 후 비슷해진 정상 문장이 분할 간에 일부 남아 있습니다. (train-test 한국어 3-gram 유사도 0.8 이상 6쌍)
- **증강 기법**: 선정 2종은 사전 기준을 통과한 기법이 아니라 경계 사례입니다. 스크리닝 유효 공격률도 15.9%, 13.6%로 낮습니다.
- **증강 중복**: 복제 행의 변형 746개 중 14개가 원본 행의 변형과 같습니다 (모두 `yamin_swap`의 짧은 정상 문장, 전체 변형의 0.1%).
- **기호 집합**: `symbol_insert`의 KOTOX 기호 74종 중 5종(`≥ㅇ≤` 등)에 한글 자모가 들어 있습니다. `symbol_insert` 변형의 약 50%에 나오며, 공격·정상 비율은 비슷합니다.
- **잘림**: 난독화 후 128 토큰을 넘는 행은 뒷부분이 잘립니다 (평가셋 1~2%, 많은 칸은 약 8%). 공격 지시는 대부분 문장 앞쪽에 있습니다.
- **KoELECTRA 투명문자**: 토크나이저가 투명문자를 지워 KoELECTRA에는 변형이 없는 것과 같습니다. 이 기법의 KoELECTRA 결과는 원문 결과와 같게 해석합니다.
- **미학습 기법 해석**: KoELECTRA에서는 학습한 `symbol_insert`와 학습하지 않은 받침 대치·도상 대치가 모두 "단어가 `[UNK]`로 바뀜"으로 보입니다. 미학습 기법의 성능이 올라도 기법 자체를 학습했다고 단정하기 어렵습니다.
- **적용률**: 연음·모음 대치 0.3처럼 적용률이 낮은 칸은 바꿀 위치가 많은(긴) 문장 위주로 평가됩니다.
